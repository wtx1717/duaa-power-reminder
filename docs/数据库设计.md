# 数据库设计

项目使用微信云数据库。集合设计以“用户配置”和“唯一电表状态”分离为核心：多个用户可以绑定同一块电表，但后台定时检查时同一电表只查一次。

## user_configs

用途：保存用户维度的核心绑定关系和提醒配置。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | 云数据库文档 ID |
| `openid` | string | 是 | 微信用户 openid |
| `lightMeterId` | string | 是 | 照明电表号 |
| `acMeterId` | string | 是 | 空调电表号 |
| `email` | string | 是 | 低电量提醒邮箱，保存前会转小写 |
| `reminderEnabled` | boolean | 是 | 当前保存配置时固定为 `true` |
| `createdAt` | Date | 是 | 创建时间 |
| `updatedAt` | Date | 是 | 更新时间 |

索引建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `openid` | 唯一索引 | 快速读取和更新当前用户配置 |
| `lightMeterId` | 普通索引 | 根据照明电表反查绑定用户 |
| `acMeterId` | 普通索引 | 根据空调电表反查绑定用户 |

## user_query_state

用途：保存用户手动查询限流状态，与核心配置分离。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | 云数据库文档 ID |
| `openid` | string | 是 | 微信用户 openid |
| `lastManualLightQueryAt` | Date | 是 | 最近一次照明手动查询时间 |
| `manualLightQueryLockUntil` | Date | 是 | 照明手动查询锁截止时间 |
| `lastManualAcQueryAt` | Date | 是 | 最近一次空调手动查询时间 |
| `manualAcQueryLockUntil` | Date | 是 | 空调手动查询锁截止时间 |
| `createdAt` | Date | 是 | 创建时间 |
| `updatedAt` | Date | 是 | 更新时间 |

索引建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `openid` | 唯一索引 | 保证每个用户只有一份手动查询状态 |

## meters

用途：按唯一电表号保存最近状态和后台调度状态。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | 云数据库文档 ID |
| `meterId` | string | 是 | 电表号 |
| `type` | string | 是 | `light` 或 `ac` |
| `lastRemainingKwh` | number | 否 | 最近一次成功解析到的剩余电量 |
| `lastQueriedAt` | Date | 否 | 最近一次查询时间，手动和后台查询都会更新 |
| `nextCheckAt` | Date | 否 | 下一次后台应纳入规划的时间 |
| `checkIntervalMinutes` | number | 否 | 查询失败时的短间隔兜底，默认 `10` |
| `estimatedDailyUsageKwh` | number | 否 | 估算日耗，默认 `5` |
| `scheduleMode` | string | 否 | `normal`、`near_threshold`、`notified` |
| `lastRechargeDetectedAt` | Date | 否 | 最近一次后台识别到充电的时间 |
| `lowPowerNotifiedAt` | Date | 否 | 当前低电量周期开始时间 |
| `failCount` | number | 是 | 连续查询失败次数 |
| `lastError` | string | 否 | 最近一次失败原因 |
| `createdAt` | Date | 是 | 创建时间 |
| `updatedAt` | Date | 是 | 更新时间 |

索引建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `meterId` | 唯一索引 | 保证同一电表只维护一份状态 |
| `nextCheckAt` | 普通索引 | `scheduledCheck` 查找到期电表 |
| `type, nextCheckAt` | 复合索引 | 后续按电表类型分批调度时使用 |

### 唯一索引部署

请在微信云开发控制台中完成 `meters.meterId` 唯一索引：

1. 打开“数据库”，进入 `meters` 集合，打开“索引管理”。
2. 新建自定义索引，字段选择 `meterId`，排序选择升序，并勾选“唯一索引”。
3. 创建索引前先清理同一 `meterId` 的重复文档；存在重复值时索引创建会失败。
4. 线上清理前先导出或备份 `meters`、`meter_check_jobs` 数据，并暂停 `scheduledCheck` 与 `scheduledCheckDispatch` 定时任务。
5. 每组重复 `meterId` 选择一个主文档，合并保留最新的 `lastRemainingKwh`、`lastQueriedAt`、`nextCheckAt`、调度模式、失败计数和提醒状态等运行态字段。
6. 将 `meter_check_jobs.meterDocId` 中指向重复文档的值改为主文档 `_id`，再删除其余重复文档。
7. 清理后重新查询确认每个 `meterId` 只有一条记录，再创建唯一索引，最后恢复定时任务。

索引创建完成后，云函数会把唯一键冲突视为并发创建的正常结果，读取已存在的 meter；没有唯一索引时，代码无法从数据库层面阻止两个请求同时插入重复文档。

## power_records

用途：保存每次电量查询结果，用于展示历史、排障和后台调度估算。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | 云数据库文档 ID |
| `meterId` | string | 是 | 电表号 |
| `remainingKwh` | number | 否 | 剩余电量，查询失败时可为空 |
| `cutoffTime` | string | 否 | 学校页面返回的截止或更新时间文本 |
| `address` | string | 否 | 学校页面解析到的地址文本 |
| `ok` | boolean | 是 | 查询是否成功 |
| `error` | string | 否 | 失败原因 |
| `queriedAt` | Date | 是 | 查询时间 |
| `type` | string | 否 | `light` 或 `ac` |
| `source` | string | 否 | `queryPower` 或 `scheduledCheck` |

索引建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `meterId, queriedAt` | 复合索引 | 查询某块电表的历史记录 |
| `queriedAt` | 普通索引 | 后续清理或统计 |
| `source, meterId, queriedAt` | 复合索引 | 后台日耗估算只读取 `scheduledCheck` 记录 |

## notification_records

用途：保存低电量邮件提醒结果，避免同一低电量周期重复发送，并支持审计。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | 云数据库文档 ID |
| `openid` | string | 是 | 接收提醒的用户 openid |
| `email` | string | 否 | 收件邮箱 |
| `meterId` | string | 是 | 触发提醒的电表号 |
| `type` | string | 否 | `light` 或 `ac` |
| `channel` | string | 否 | 当前为 `email` |
| `remainingKwh` | number | 是 | 触发时剩余电量 |
| `thresholdKwh` | number | 是 | 本次提醒使用阈值，当前为 `20` |
| `sentAt` | Date | 是 | 发送或尝试发送时间 |
| `status` | string | 是 | `sent`、`failed`、`skipped` |
| `source` | string | 否 | 当前后台提醒写入 `scheduledCheck` |
| `error` | string | 否 | 发送失败或跳过原因 |

索引建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `openid, sentAt` | 复合索引 | 查看用户提醒历史 |
| `meterId, sentAt` | 复合索引 | 查看电表提醒历史 |
| `openid, meterId, type, channel, status, sentAt` | 复合索引 | 判断当前低电量周期是否已成功发送 |

## job_locks

用途：防止 `scheduledCheck` 并发执行导致重复规划。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | 云数据库文档 ID |
| `name` | string | 是 | 锁名，当前为 `scheduledCheck` |
| `lockedUntil` | Date | 是 | 锁过期时间 |
| `owner` | string | 是 | 本次任务实例标识 |
| `updatedAt` | Date | 是 | 更新时间 |

索引建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | 唯一索引 | 同一种任务只允许一把锁 |
| `lockedUntil` | 普通索引 | 判断或清理过期锁 |

## meter_check_jobs

用途：保存后台检查的随机错峰计划。`scheduledCheck` 生成任务，`scheduledCheckDispatch` 执行任务。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | 云数据库文档 ID |
| `meterDocId` | string | 否 | 对应 `meters` 文档 ID |
| `meterId` | string | 是 | 电表号 |
| `type` | string | 是 | `light` 或 `ac` |
| `status` | string | 是 | `pending`、`running`、`done`、`failed`、`expired` |
| `runId` | string | 是 | 本轮规划实例标识 |
| `plannedAt` | Date | 是 | 随机分配后的实际执行时间 |
| `deadlineAt` | Date | 是 | 本轮任务截止时间 |
| `attempts` | number | 否 | 抢占执行次数 |
| `error` | string | 否 | 失败或过期原因 |
| `createdAt` | Date | 是 | 创建时间 |
| `updatedAt` | Date | 是 | 更新时间 |
| `startedAt` | Date | 否 | 实际开始执行时间 |
| `finishedAt` | Date | 否 | 实际结束时间 |

索引建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status, plannedAt` | 复合索引 | 分发器读取到点任务 |
| `meterId, status` | 复合索引 | 规划阶段跳过已有未完成任务 |
| `deadlineAt` | 普通索引 | 清理过期任务 |
